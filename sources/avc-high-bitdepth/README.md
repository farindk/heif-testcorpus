# avc-high-bitdepth

Generated AVC images at bit depths that the common encoders cannot produce.
x264 encodes 8 and 10 bits per sample only, while ISO/IEC 14496-10 allows 8
to 14 bits and decoders such as FFmpeg implement 9, 12 and 14 bits as well.

| | |
|---|---|
| Origin | Generated by `build.py`, no third-party material |
| Files | 6 images with one raw reference file each, 1.3 MB |
| Licence | MIT, as the scripts of this repository (see `LICENSE`) |

## Files

All pictures are 256x128, full range, with colour primaries 1 (BT.709) and
transfer characteristics 13 (sRGB).

| File | Bit depth | Chroma format | Matrix coefficients | AVC profile | FFmpeg pixel format |
|---|---|---|---|---|---|
| `avc-9bit-400.heif` | 9 | 4:0:0 | 6 (BT.601) | High 10 | `yuv420p9le`, see below |
| `avc-9bit-420.heif` | 9 | 4:2:0 | 6 (BT.601) | High 10 | `yuv420p9le` |
| `avc-9bit-422.heif` | 9 | 4:2:2 | 6 (BT.601) | High 4:2:2 | `yuv422p9le` |
| `avc-9bit-444.heif` | 9 | 4:4:4 | 6 (BT.601) | High 4:4:4 Predictive | `yuv444p9le` |
| `avc-9bit-444-gbr.heif` | 9 | 4:4:4 | 0 (identity, GBR) | High 4:4:4 Predictive | `gbrp9le` |
| `avc-14bit-444-gbr.heif` | 14 | 4:4:4 | 0 (identity, GBR) | High 4:4:4 Predictive | `gbrp14le` |

## Picture content

A colour gradient: hue runs from left to right through red, yellow, green,
cyan, blue and magenta. The top row is white, the rows in the middle have
full saturation, and the bottom row is black. Every component of the RGB
picture covers the whole range from 0 to the highest code value.

The files with matrix coefficients 0 store the RGB picture unchanged, with
G, B and R in the planes that otherwise hold Y, Cb and Cr. The other files
store it converted to full range YCbCr with the BT.601 coefficients; for
4:2:2 and 4:2:0 the chroma planes are averaged over 2x1 and 2x2 samples.
`avc-9bit-400.heif` contains the luma plane only. All arithmetic is done on
integers, see `build.py` for the exact rounding.

## Coding

Each picture is a single IDR slice that consists of I_PCM macroblocks only
(CAVLC, deblocking disabled). I_PCM stores the samples uncompressed at the
coded bit depth. The pictures are therefore lossless, and the decoded planes
are known exactly without trusting any encoder or decoder.

- The picture size is a multiple of 16, there is no frame cropping.
- `level_idc` is 51. The limit on the size of an access unit (A.3.3, MinCR)
  is derived from the macroblock rate of the level, and an uncompressed
  picture of this size exceeds it at the low levels.
- The colour description is written to the VUI and, with the same values, to
  a `colr` box of type `nclx`.

## Container

One `avc1` image item with the properties `avcC` (essential), `ispe`, `colr`
and `pixi`. The files carry the brand `mif1` only. They do not claim `avci`,
because that brand requires the Constrained High profile (ISO/IEC 23008-12
E.4.1.1), which is limited to 8 bits and 4:2:0.

## Reference files

`<name>.<pixel format>.raw` holds the expected decoded planes of
`<name>.heif` in coding order (Y, Cb, Cr or G, B, R), every plane in its own
resolution, as 16 bit little endian samples without any header. The pixel
format in the file name is the FFmpeg name of this layout, so a reference
can be viewed or converted with

```
ffmpeg -f rawvideo -pix_fmt gbrp9le -s 256x128 -i avc-9bit-444-gbr.gbrp9le.raw out.png
```

A decoder under test has to reproduce the reference exactly. With libheif,
decode with `heif_colorspace_undefined` and `heif_chroma_undefined` and set
`output_image_nclx_profile_passthrough` in the decoding options. Without
the passthrough flag libheif converts the identity matrix files to its
default matrix coefficients and the planes differ from the reference.

`avc-9bit-400.heif` is coded without chroma planes and its reference holds
the luma plane only. FFmpeg's AVC decoder has no monochrome output and
delivers this picture as 4:2:0 with both chroma planes set to the mid value
256. Compare the luma plane only.

## Verification

Performed on 2026-09-29 for the pinned outputs:

- FFmpeg 6.1.1 decodes the AVC bitstream of every file (byte stream format,
  outside of the container) to exactly the reference file, reports the
  profile and pixel format listed above, and prints no warning with
  `-strict very -err_detect explode`.
- The `trace_headers` bitstream filter of FFmpeg parses the parameter sets
  and the slice header to the values that the generator wrote.
- libheif with its FFmpeg decoder plugin decodes all six files to exactly
  the reference planes, under AddressSanitizer and
  UndefinedBehaviorSanitizer. The 9 bit files need
  [pull request #1920](https://github.com/strukturag/libheif/pull/1920),
  the 14 bit file needs the follow-up commit "FFmpeg decoder: support 14-bit
  planar GBR output". libheif 1.23.5 rejects all six with "Pixel format not
  implemented".
- MP4Box and `heif-info -d` parse the container without complaints.
